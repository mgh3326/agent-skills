# ask-session — 세션 질의·답변 회수 왕복

**원칙: 침묵은 답변이 아니다.** 답변 파일이 기한 내 없으면 "무응답"이 결과다 — 추측으로
채우거나, 이전 대화 내용을 답변인 양 인용하거나, 무한 재질의하지 않는다.

## 1. 질의 구성 — 답변 계약을 질문에 포함

- **답변 파일 경로를 질문자가 지정**: `~/work/herdr-inbox/answer-<질문자>-<주제>-<HHMM>.md`
  (유일 이름, 질의 전 `ls`로 부재 확인). 화면 답변은 유실되니 **파일 작성이 계약**이다.
- 질문에 반드시 포함: ①누가 왜 묻는지(출처) ②답변 형식(요약/표/판정 등) ③기한
  ("<N>분 내") ④"모르면 '모름'과 그 근거를 적어라 — 추측 금지" ⑤답변 파일 경로.
- 답변자는 답변 파일 작성 직후 아래 통지를 반드시 실행한다:

  ```bash
  panewire emit --kind lane.event --lane <요청자 레인> --event-id <고유id> --text '[consult-done] <1줄 요지> | <답변 파일 경로>'
  ```
- 머리에: `(같은 질문이 두 번 보이면 재답변 금지)`.

## 2. 주입 — relay-handoff 절차 재사용

- 질의 전 요청자 레인이 hub에 등록되어 있는지 확인한다. 미등록 레인의 emit은 조용히 유실된다.
- **relay-handoff 스킬의 §2(대상 검증)·§3(주입+제출 검증)을 그대로 따른다.**
- 대상 해석은 **`wrk find <이름|라벨>`** 로 한다(이름 유실 시 라벨 폴백 + 화면 미리보기).
- 대상이 이름·라벨 모두로 안 잡히면(세션 사망·재시작) **실패로 보고하고 운영자
  에스컬레이션** — 질문자가 임의로 대상 세션을 재스폰하지 않는다(orch/빌더 재생성은
  운영자 결정).

## 3. 답변 대기·회수

- 답변자는 답변 파일을 작성한 직후 아래 통지를 반드시 실행한다:

  ```bash
  panewire emit --kind lane.event --lane <요청자 레인> --event-id <고유id> --text '[consult-done] <1줄 요지> | <답변 파일 경로>'
  ```
- 질의자는 답변 파일을 주기적으로 확인하지 않는다. `lane.event`를 기다리며 현재 턴을
  양보하고, 이벤트를 받으면 이벤트에 적힌 답변 파일을 1회 확인한다.
- 패킷에 명시한 기한이 경과한 때에만 답변 파일을 1회 확인한다. 없으면
  ①`herdr agent read <target> --lines 40`으로 답변이 화면에만 있는지 확인 — 있으면
  "파일 미작성, 화면 전사본" 명시 ②없으면 "무응답 (기한 N분 경과)"으로 보고하고
  운영자에게 표면화한다. 재질의는 1회까지, 헤더에 `[재질의 — 이전 질의 무응답]`을
  명시한다.
- `herdr agent wait --status idle`은 보조 상태 신호일 뿐이며 완료 통지는 `lane.event`로
  받는다. kiro/agy는 작업 중에도 idle/done 오표시(status 플랩), claude는 다른 작업으로
  working일 수 있다.
- `panewire emit` 의 `rc=0` 은 hub 가 요청을 접수했다는 뜻일 뿐 배달 증거가 아니다.
- 등록은 필요조건이지 충분조건이 아니다. 2026-09-14 실측에서 hub 등록이 완료되고 `emit` 이 rc=0 을 반환했는데도 일부 pane 종류(당시 grok·devin)에서 `lane.event` 가 도착하지 않았다 (관측 가능한 부작용을 요구하는 프로브가 120~150초 동안 실행되지 않았고, 그동안 그 pane 은 정상 작업 중이었다). claude 계열 pane 에서는 정상 배달됐다. 원인 수리 전까지, 통지가 오지 않는 것이 곧 답변이 없다는 뜻은 아니다.

## 4. 보고 형식

- 질문 요지 1줄 / 답변 파일 경로 + 핵심 답변 / 왕복 소요 시간
- 무응답·화면전사·재질의였다면 그 사실을 그대로 (정상 왕복인 척 금지)

## 설계 배경

- 답변 채널이 파일인 이유: 세션 pane에 send로 회신하면 사용자 타이핑과 충돌(실사고),
  화면 출력은 스크롤/compact로 유실된다. 인박스 파일은 durable하고 어느 에이전트든 읽는다.
- 이 스킬은 relay-handoff(단방향 전달)의 왕복 확장이다 — 질의도 결국 "답변 계약이 붙은
  릴레이"다.

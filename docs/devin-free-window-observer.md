# Devin SWE-2 free-window observer

Install scopefuel before agent-skills. The oldest scopefuel commit that accepts `observe devin-free-limit` is `99abef2b3b8636d06b04080b90b047dad79a0ec7`. Full compatibility with this observer, including observations from paid Devin rungs, requires `542a8c744b9e012b095ef345eff3501f8bfcddbc` or newer. Older scopefuel versions reject the command; the completion sentinel records the failure and continues the job lifecycle.

For Devin-kind jobs, wrk reads only the pane's bounded `recent-unwrapped` transcript. It records a matching rate-limit message once per job/reset, with the observed time, reset, actual source rung, and job id. Scopefuel accepts actual Devin profile UIDs for the observation record, but only the hold members are included in gate and recommendation denial: the six free SWE-2 names and, since hk 1729 r2, devin-fusion-sol61 and devin-fusion-sol61-xhigh, whose panes stall when the free SWE-2 sidekick window is exhausted. Scopefuel keeps that membership in one place; agent-skills holds no copy of it. Fusion-Sol rungs need scopefuel PR 157 (hk 1729), branch commit `a762c2a56853a6af4fdab22087d6031e290af15c`, or newer; an older scopefuel rejects their observations. The observer resolves the installed wrk symlink before locating its helper. It does not read agent configuration or credentials and does not send pane input. Other providers do not enter this read path.

The parser accepts the rate-limit sentence only inside the provider error block: a U+25B2 triangle followed by Something went wrong, then an indented body beginning with Reached free model rate limit. It parses reset details only from that body, including when the phrase or time wraps across pane lines. Numbered source, diffs, code blocks, shell echo or grep output, and quoted brief or prompt text outside the block are ignored. If a quoted copy appears before a real block in the same pane window, the reset is taken from the real block.

The current Devin provider does not expose a stable account fingerprint, so the observer normally keys the record by a host and Unix-user hash. That fallback is host-local and can group multiple Devin accounts used by the same Unix user. The existing quota-share channel keys remote records by account fingerprint and publishes or reads only with an account-kind fingerprint; it cannot bind this observation to a Devin account today. A new observation type alone would not solve that missing identity. Cross-host support requires a credential-free Devin account identity as well as a typed quota-share writer and gate-time reader.
